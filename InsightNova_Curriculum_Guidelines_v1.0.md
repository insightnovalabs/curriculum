# Curriculum Development Guidelines

Version 1.0 \| 25 November 2026

Learn • Practice • Build

## Purpose and scope

Apply these standards to Instagram, GitHub and future website learning
materials. Preserve the 139-module inventory, original IDs, ten phases
and 16 separate industry pathways. Project content remains empty until
approved.

## Classification

-   A: Core modules - mandatory for the general pathway.

-   B: Additional professional skills - optional.

-   C: Advanced specialization - optional.

## Progressive learning

-   Beginner: fundamental concepts, simple examples and guided
    exercises.

-   Intermediate: practical implementation, deeper theory and
    independent problem-solving.

-   Expert: advanced concepts, optimization, professional and
    research-level material where applicable.

Learners progress across relevant modules in passes, rather than
mastering every expert topic before moving on. Prerequisites and exact
sequence will be established in the Master Learning Roadmap.

## Standard teaching framework

-   1.  Introduction - introduce the subject
-   2.  Prerequisites - identify prior knowledge
-   3.  Learning objectives - define measurable outcomes
-   4.  Theory - explain concepts
-   5.  Practical examples - demonstrate application
-   6.  Exercises - develop independent problem-solving
-   7.  Solutions - explain correct approaches
-   8.  Common mistakes - address misconceptions
-   9.  Knowledge assessment - evaluate understanding
-   10. Summary - reinforce concepts
-   11. References - provide credible resources

## Approved scope extensions

The following are syllabus requirements, not additional modules.
Detailed topic sequencing and assessments remain to be developed.

### Phase 1

Files, directories, operating systems, binary numbers, memory,
pseudocode, flowcharts, command line, algorithms, critical thinking and
interpretation.

### Phase 2

Regular expressions, file handling, generators, iterators, decorators,
type hints, logging, unit and integration testing, SciPy, package
development, time and space complexity and Big O.

### Phase 3

Probability distributions, sampling theory, confidence intervals,
statistical power, effect sizes, maximum likelihood, bootstrapping,
numerical optimization, multiple hypothesis testing, numerical
precision, notation, functions, eigenvalues, eigenvectors, SVD, matrix
decompositions, partial derivatives, multivariable calculus, chain rule,
GLMs, ANOVA, hierarchical and mixed-effects models, estimation theory,
gradient descent, convex and constrained optimization.

### Phase 4

Indexing, transactions, ACID, Airflow, dbt, Kafka, Spark, Delta Lake,
Iceberg and pipeline testing.

### Phase 5

Cohorts, funnels, customer segmentation, retention, sensitivity
analysis, dashboard design, stakeholder communication, report writing,
missing-data mechanisms, imputation, literature reviews, research
validity and reproducibility.

## Approved scope extensions (continued)

### Phase 6

Data leakage, train-test contamination, bias-variance trade-off,
underfitting, overfitting, regularization, scikit-learn pipelines,
baselines, cross-validation, cost-sensitive learning, SHAP, LIME, model
selection, error analysis, inductive bias, generalization, learning
paradigms, statistical comparison and subgroup evaluation.

### Phase 7

Embeddings, loss functions, optimizers, batch normalization, dropout,

Tokenization, semantic search, embedding models, vector search,

### Phase 9

Model monitoring, data and concept drift, experiment tracking,
registries, MLflow, automated retraining, cloud security, cost
optimization, GDPR, AI regulation, ownership, licensing, consent,
retention, accessibility, social impact, fairness and human oversight.

### Phase 10

Project content remains empty.

## Editorial boundaries

Keep overlapping modules distinct: statistical inference versus
prediction; cleaning versus preprocessing; infrastructure versus ETL;
architecture versus generative AI applications; ethics versus technical
safety; MLOps versus DataOps; visualization versus BI.

## Proposed editorial workflow

Draft, verify technical accuracy, test examples and solutions, review
accessibility and references, then publish. Record revisions and
preserve module IDs. This workflow is an implementation recommendation,
not an additional approved curriculum decision.
